1. Ray Generation & Bounding-Sphere Clipping ([tenter,texit][t_{\text{enter}}, t_{\text{exit}}][tenter​,texit​])#

Algebraic surfaces like a hyperboloid (x2+y2−z2−1=0x^2 + y^2 - z^2 - 1 = 0x2+y2−z2−1=0) or Whitney's Umbrella (x2−y2z=0x^2 - y^2 z = 0x2−y2z=0) extend to infinity in R3\mathbb{R}^3R3. To inspect them as tangible 3D sculptures—just like the physical plaster models of 19th-century German mathematics collections and Oberwolfach's SURFER—we intersect the infinite surface with a clipping sphere of radius RRR:

BR={p∈R3  |  ∥p∥2=x2+y2+z2≤R2}\mathcal{B}_R = \left\{ \mathbf{p} \in \mathbb{R}^3 \;\middle|\; \|\mathbf{p}\|^2 = x^2 + y^2 + z^2 \le R^2 \right\}BR​={p∈R3​∥p∥2=x2+y2+z2≤R2}

For each screen pixel with normalized device coordinates (u,v)∈[−1,1]2(u, v) \in [-1, 1]^2(u,v)∈[−1,1]2, the vertex and fragment stages transform the camera eye position and pixel plane into object-space ray origin o\mathbf{o}o and normalized ray direction d\mathbf{d}d (∥d∥=1\|\mathbf{d}\| = 1∥d∥=1).

Before evaluating the user's polynomial f(p)f(\mathbf{p})f(p) a single time, the fragment shader solves the quadratic ray-sphere intersection ∥o+td∥2=R2\|\mathbf{o} + t\mathbf{d}\|^2 = R^2∥o+td∥2=R2:

t2+2(o⋅d)t+(∥o∥2−R2)=0t^2 + 2(\mathbf{o} \cdot \mathbf{d})t + \left(\|\mathbf{o}\|^2 - R^2\right) = 0t2+2(o⋅d)t+(∥o∥2−R2)=0

glsl
bool intersectBoundingSphere(vec3 ro, vec3 rd, float radius, out float tEnter, out float tExit) {
    float b = dot(ro, rd);
    float c = dot(ro, ro) - radius * radius;
    float disc = b * b - c;
    if (disc < 0.0) return false; // Ray misses the bounding sphere completely!
    
    float sqrtDisc = sqrt(disc);
    tEnter = max(0.0, -b - sqrtDisc);
    tExit  = -b + sqrtDisc;
    return tExit > tEnter;
}

This simple test provides two massive wins on a mobile tile-based GPU:

  1. Early Background Culling: Every pixel outside the silhouette of the bounding sphere immediately exits (discard or writes background color) in 6 ALU instructions without running the raymarcher.
  2. Tightly Bounded Search Interval: The search for roots of g(t)=f(o+td)=0g(t) = f(\mathbf{o} + t\mathbf{d}) = 0g(t)=f(o+td)=0 is strictly confined to the finite chord [tenter,texit][t_{\text{enter}}, t_{\text{exit}}][tenter​,texit​] of length at most 2R2R2R.

2. Root Isolation Along the Ray: Finding the First Sign Change#

Along the bounded ray segment t∈[tenter,texit]t \in [t_{\text{enter}}, t_{\text{exit}}]t∈[tenter​,texit​], a degree-ddd algebraic surface can intersect the viewing ray up to ddd times. For occlusion to be physically correct, we must find the smallest root t∗∈[tenter,texit]t^* \in [t_{\text{enter}}, t_{\text{exit}}]t∗∈[tenter​,texit​] (the surface sheet closest to the camera).

For low-degree surfaces (d≤4d \le 4d≤4), closed-form algebraic formulas exist (the quadratic formula for d=2d=2d=2, Cardano's formula for cubics d=3d=3d=3, and Ferrari's resolvent cubic for quartics d=4d=4d=4—all of which we later implemented as specialized fast-paths in SurfZar).

For general degree-ddd equations (d=5,6,…d = 5, 6, \dotsd=5,6,…) and arbitrary user expressions, the shader partitions [tenter,texit][t_{\text{enter}}, t_{\text{exit}}][tenter​,texit​] into NNN marching steps of size Δt=(texit−tenter)/N\Delta t = (t_{\text{exit}} - t_{\text{enter}}) / NΔt=(texit​−tenter​)/N and scans forward from tentert_{\text{enter}}tenter​ to texitt_{\text{exit}}texit​:

glsl
float tPrev = tEnter;
float fPrev = f(ro + rd * tPrev);
float rayHitSign = sign(fPrev); // Tracks whether ray approaches from f > 0 or f < 0
bool foundBracket = false;
float tA = tEnter, tB = tEnter;

for (int i = 1; i <= MAX_STEPS; i++) {
    float tCurr = tEnter + float(i) * dt;
    float fCurr = f(ro + rd * tCurr);
    
    // Intermediate Value Theorem: opposite signs guarantee a root in [tPrev, tCurr]
    if (fPrev * fCurr <= 0.0) {
        tA = tPrev;
        tB = tCurr;
        foundBracket = true;
        break; // Stop at the FIRST (closest to camera) intersection!
    }
    tPrev = tCurr;
    fPrev = fCurr;
}

3. Why Pure Newton-Raphson Explodes at Singularities—and How Safeguarded Newton-Bisection Solves It#

Once the marching loop isolates a bracket [ta,tb][t_a, t_b][ta​,tb​] where g(ta)g(t_a)g(ta​) and g(tb)g(t_b)g(tb​) have opposite signs, the naive textbook approach is to run Newton-Raphson iterations:

tk+1=tk−g(tk)g′(tk),where g′(tk)=∇f(o+tkd)⋅dt_{k+1} = t_k - \frac{g(t_k)}{g'(t_k)}, \quad \text{where } g'(t_k) = \nabla f(\mathbf{o} + t_k \mathbf{d}) \cdot \mathbf{d}tk+1​=tk​−g′(tk​)g(tk​)​,where g′(tk​)=∇f(o+tk​d)⋅d

On an algebraic surface, unconstrained Newton-Raphson produces severe visual artifacts along two critical regions:

  1. Silhouette Grazing Edges (∇f⋅d≈0\nabla f \cdot \mathbf{d} \approx 0∇f⋅d≈0): Along the silhouette rim of any curved surface, the viewing ray d\mathbf{d}d is perpendicular to the surface normal ∇f\nabla f∇f, so the directional derivative g′(tk)g'(t_k)g′(tk​) approaches zero. Dividing by g′(tk)≈10−7g'(t_k) \approx 10^{-7}g′(tk​)≈10−7 launches tk+1t_{k+1}tk+1​ tens of units outside the bracket [ta,tb][t_a, t_b][ta​,tb​], causing the pixel to either miss the surface (leaving a sparkly black halo around silhouettes) or jump onto a completely different sheet behind the surface!
  2. Singular Points (∇f=0\nabla f = \mathbf{0}∇f=0): At a conical double point or self-intersection, all three partial derivatives vanish simultaneously, making g′(tk)=0g'(t_k) = 0g′(tk​)=0.

The Safeguarded Hybrid Bisection + Newton Solver#

To combine the unconditional stability of Bisection with the quadratic convergence speed of Newton-Raphson, we implemented a Safeguarded Hybrid Root Refiner:

glsl
float refineRootHybrid(vec3 ro, vec3 rd, float a, float b, float fa, float fb) {
    float t = 0.5 * (a + b);
    
    for (int iter = 0; iter < 10; iter++) {
        vec3 p = ro + rd * t;
        float ft = f(p);
        
        // Maintain the tight sign-change bracket [a, b]
        if (fa * ft <= 0.0) {
            b = t;
            fb = ft;
        } else {
            a = t;
            fa = ft;
        }
        
        // Evaluate directional derivative g'(t) = dot(grad_f(p), rd)
        float dfdt = dot(grad_f(p), rd);
        float newtonCandidate = t - ft / dfdt;
        
        // Safeguard: only accept the Newton step if derivative is non-degenerate
        // AND the candidate stays strictly inside theshrinking bracket (a, b)!
        if (abs(dfdt) > 1e-4 && newtonCandidate > a && newtonCandidate < b) {
            t = newtonCandidate;
        } else {
            // Fall back to guaranteed Bisection midpoint
            t = 0.5 * (a + b);
        }
    }
    return t;
}

Look at why this 25-line function is rock-solid on the GPU:

  • Unconditional Loop Unrolling: Because the loop bound (10 iterations) is a compile-time constant with no dynamic break, the OpenGL ES 2.0 shader compiler unrolls it cleanly without warp divergence.
  • Guaranteed Bracket Contraction: Even right on top of one of the 65 conical singularities of the Barth Sextic where abs(dfdt) <= 1e-4, the solver smoothly falls back to t = 0.5 * (a + b), shrinking the bracket by 210=1024×2^{10} = 1024\times210=1024× beyond the initial step size Δt\Delta tΔt!
  • Quadratic Polish on Smooth Sheets: Everywhere else on the surface, the Newton step lands strictly inside (a, b) and converges to full 23-bit IEEE highp float mantissa precision in just 3–4 iterations.

4. Two-Sided Manifold Orientation (rayHitSign) & Shading#

An implicit surface f(x,y,z)=0f(x, y, z) = 0f(x,y,z)=0 divides R3\mathbb{R}^3R3 into two distinct half-spaces:

  • The Positive Side (f(x,y,z)>0f(x,y,z) > 0f(x,y,z)>0): Where the gradient vector ∇f\nabla f∇f points outward.
  • The Negative Side (f(x,y,z)<0f(x,y,z) < 0f(x,y,z)<0): Where ∇f\nabla f∇f points inward.

When viewing a clipped algebraic surface (or slicing through an internal chamber), the camera sees both the exterior (f>0f > 0f>0) and interior (f<0f < 0f<0) faces of the polynomial sheet. Following the visual tradition of Oberwolfach's SURFER, coloring the two sides with contrasting materials immediately reveals the global topology and orientation of the manifold:

glsl
vec3 hitPos = ro + rd * tStar;
vec3 rawGrad = grad_f(hitPos);
vec3 N = normalize(rawGrad);

// Orient normal toward the approaching camera ray
bool isFrontFace = (rayHitSign > 0.0);
if (dot(N, rd) > 0.0) {
    N = -N;
}

// Select Side A (f > 0) vs Side B (f < 0) base albedo
vec3 baseColor = isFrontFace ? uColorFront : uColorBack;

Notice a subtle detail here: why do we determine isFrontFace from rayHitSign (the sign of fff at the start of the marching interval before hitting the surface) rather than from dot(rawGrad, rd)? Because on thin sheets or near singular creases, small floating-point inaccuracies in hitPos can cause rawGrad to jitter near zero, producing "zebra stripe" color flickering between Front and Back colors! Using the approaching sign rayHitSign guarantees that the positive and negative sides of the surface never flicker.
